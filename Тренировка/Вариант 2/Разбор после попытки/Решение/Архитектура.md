# Как устроен обмен между Производством и Трейдом

## А Производство

Типовой справочник, наборы дополнительных реквизитов категорий, прикреплённые файлы, установка цен и оприходование запасов хранят результат в УНФ. В модуле импорта штатная обработка УНФ «Загрузка данных из файла» разбирает все строки Excel через ЗаполнитьТаблицуСопоставленияДаннымиИзШаблона. Заголовки связываются с внутренними именами полей, а артикулы и штрихкоды читаются как текст. Расширение берёт полученные строки для записи групп, карточек, цен, остатков и изображений. Тот же типовой загрузчик можно открыть из формы для интерактивной подготовки. Расширение обрабатывает согласованную поставку одной транзакцией. Оно ищет артикулы внутри трёх учебных ветвей и на повторе обновляет учебные документы. Подсчёт по одному артикулу без отбора по учебной ветви захватывает посторонние товары демобазы. Исходные 13 цифр штрихкода сохраняются для сверки со столбцом G. Контрольная цифра EAN-13 правильна у пяти исходных значений из 38.

## Б Публикация и клиент

В базе Производство командой подготовки доступа создаются пользователь площадки, набор ролей и состав стандартной публикации. Трейд хранит профиль, пароль помещается в безопасное хранилище БСП. Список читается страницами по 16 записей; в окне выводятся таблица и число загруженных строк. HTTP-клиент принимает JSON. На 401 выводится сообщение о логине и пароле, на 403 о правах, на 404 о ресурсе, другие статусы показываются вместе с ответом сервера.

После корня standard.odata/ подставляй ресурс. Значения в фигурных скобках замени UID из своей базы. УНФ 3.0.9.150 поддерживает раскрытие контрагента в запросе к коллекции. Для одного документа связанный объект доступен по навигационному адресу.

```text
GET Catalog_Номенклатура?$format=json&$filter=Parent_Key eq guid'{папка}'&$select=Ref_Key,Description,Артикул&$orderby=Description asc
GET Document_ЗаказПокупателя?$format=json&$filter=Ref_Key eq guid'{заказ}'&$select=Ref_Key,Контрагент&$expand=Контрагент
GET Document_ЗаказПокупателя(guid'{заказ}')/Контрагент?$format=json
POST Document_ЗаказПокупателя?$format=json
```

## В Каталог Трейда

Синхронизация ограничивает выборку тремя учебными деревьями. Сначала обрабатываются родители, затем дочерние позиции. При первой загрузке поиск существующей карточки учитывает полное имя, неоднозначность останавливает операцию. Для повторной загрузки используется составной ключ регистра из двух измерений, UID производителя и ссылки ЛокальнаяНоменклатура. Ресурс Номенклатура прежней версии сохраняет совместимость. При первой синхронизации расширение переносит старые записи в новый ключ под блокировкой. Торговый каталог читает остаток по HTTP, собственный остаток по складу и закупочную цену. Условие подсветки — собственный остаток равен нулю при положительном количестве у производителя.

## Г Заказ и его состояние

Форма каталога переносит отмеченные позиции и закупочную цену. Подтверждение показывает число строк и сумму. По внешнему UID каждой позиции собирается POST заказа. Ключ запроса и маркер исходного документа позволяют восстановить связь после повторной отправки. В Трейде сохраняется UID производителя. Обновление состояния записывает типовое состояние УНФ и представление для цветового индикатора. При изменении создаются запись журнала и напоминание автору. Второй опрос того же состояния пропускает эти операции. Регламент задан по будням с 08:00 до 20:00 с интервалом 300 секунд. Тайм-аут HTTP равен 10 секундам.

## Д Потребность и закупка

Восемь карточек получат способ «Закупка», срок два дня, поставщика и границы запасов. Штатный менеджер обработки УНФ «РасчетПотребностей» рассчитывает дефицит. Для отбора задания расширение сравнивает собственный остаток с минимумом строго по условию «меньше». Это важно для 1003: при остатке 30, минимуме 30 и максимуме 80 типовая таблица может рекомендовать ещё 50. В контрольном заказе этого артикула нет. У остальных дефицитных позиций в заказ передаётся количество из дерева рекомендаций УНФ. Цена поступает из каталога производителя.

Для показа открой вкладку клиентского заказа, документ покупателя и торговый заказ заранее. Участнику и руководителю адресованы разные реплики и контрольные карточки на последней странице Методички 2.


## Воспроизводимая проверка закупки

В Трейде укажи склад контрольного прихода. Для товаров 1002, 2005, 3001, 4004 и 5001 ожидаются 48, 120, 140, 40 и 46 единиц. У 1003 остаток равен минимуму, у 3102 и 6002 остаток выше него. Эти три позиции пропускаются. Сумма пяти строк равна 394. Типовой расчёт отдаёт дерево по восьми карточкам. Расширение применяет к узлам условие «собственный остаток строго ниже минимума» и использует рекомендацию из дерева в заказе поставщику.

Открой Vanessa Automation с подключённым TestClient в учебном Трейде и загрузи «Пополнение.feature». Сценарий вызывает кнопки формы и сравнивает пять строк с ожидаемыми значениями. В протоколе приведён отдельный прогон штатного расчёта через платформу 1С. Затем нажми «Сформировать заказ» и сверь поставщика, пять количеств и сумму в единицах.
