# ОфисПро · Тренажёр OData для модуля Б

За одну тренировку вы подключите клиент к производителю, прочитаете каталог, цены и остатки, оформите заказ и сверите его по UID. Сервис работает локально на Python 3.9+ со стандартной библиотекой. Для первого прогона достаточно браузера. К тем же адресам можно направить запросы из собственной обработки 1С.

## Первый запуск

1. Распакуйте архив в отдельную папку. Откройте в ней терминал.
2. На macOS или Linux выполните `python3 trainer.py`. На Windows выполните `py -3 trainer.py`.
3. Задайте учебный пароль пользователя `odata_user`. Для репетиции по условию введите пароль из задания. Символы при вводе в терминале скрыты.
4. Откройте в браузере **http://127.0.0.1:8080/**. Введите тот же пароль и нажмите **Проверить подключение**. Ожидаются HTTP 200 и девять ресурсов.
5. Начните с вкладки **Самопроверка**. Решите задания на соседних вкладках или в своей обработке. Вернитесь сюда, введите числа и UID заказа, нажмите **Сверить результаты**.

Окно терминала должно оставаться открытым. Для остановки нажмите Ctrl+C. Заказы сохраняются в файле `orders.sqlite3` рядом с программой. Для новой попытки с отдельной историей запустите `python3 trainer.py --db attempt-2.sqlite3`. Если порт занят публикацией УНФ, добавьте `--port 8081` и откройте адрес, который напечатает сервис. Для автоматизированного запуска поддерживается переменная окружения `OFFICEPRO_PASSWORD`.

## Маршрут на три часа

| Время | Что сделать | Что предъявить при самопроверке |
| --- | --- | --- |
| 0–30 минут | Проверьте корень и `$metadata` в тренажёре. Затем потренируйтесь публиковать копию «ОфисПро Производство» в Конфигураторе, включите стандартный интерфейс OData, настройте состав объектов и права учебного пользователя на чтение и создание заказа | Список ресурсов, код 200 с учётными данными и код 401 без них |
| 30–90 минут | В своей обработке сделайте поля подключения, индикатор результата, таблицы номенклатуры, остатков и цен. Получите все страницы. Сравните с браузерным клиентом | 500 товаров, 500 строк остатков и 1 000 строк цен |
| 90–120 минут | На вкладке произвольного запроса проверьте четыре параметра из упражнений ниже. Проверьте обработку 401, 404 и 500 | Отобранные строки, выбранные поля, порядок и раскрытая связь |
| 120–155 минут | Отправьте заказ из клиента. Прочитайте именно созданный документ по вернувшемуся Ref_Key. Для проверки в настоящей УНФ повторите POST через её публикацию и откройте документ в базе производителя | Дата, покупатель, две номенклатурные позиции, количество, цена, сумма и UID |
| 155–180 минут | Оформите описание API и архитектуры модуля Б. Сохраните примеры успешного GET, POST и сообщения об ошибке | Клиент, описание API, документ архитектуры и созданный заказ для демонстрации |

В тренажёре девять наборов данных уже опубликованы. Настройка веб-сервера, роли пользователя в Конфигураторе и открытие настоящего документа выполняются в своей учебной УНФ. Учебные заказы Python хранятся в SQLite. Для реальной публикации получите UID покупателя и товаров заново. Для файловой 1С в виртуальной машине запустите тренажёр внутри той же ВМ. Для клиент-серверной базы `127.0.0.1` указывает на машину, где выполняется HTTP-вызов.

## Адрес и ресурсы

Корень для HTTP Basic — `http://127.0.0.1:8080/unf_production/odata/standard.odata/`. Передавайте логин и пароль через Basic Authentication. Ответы ресурсов имеют формат JSON. Метаданные возвращаются в XML. Коллекция лежит в массиве `value`. Следуйте по `odata.nextLink` до последней страницы. Максимальный размер страницы тренажёра — 100 строк. Вкладка «Произвольный запрос» принимает имя ресурса относительно корня. Параметры вводятся в отдельные поля, браузер кодирует URL.

| Ресурс | Действие и поля |
| --- | --- |
| Корень, `$metadata` | GET списка наборов и XML со схемой полей и связей |
| `Catalog_Номенклатура` | GET товаров и папок. Ref_Key, Description, Артикул, IsFolder, Parent_Key, DeletionMark |
| `AccumulationRegister_ЗапасыНаСкладах/Balance` | GET остатков. Номенклатура_Key, СтруктурнаяЕдиница_Key, КоличествоBalance |
| `InformationRegister_ЦеныНоменклатуры/SliceLast` | GET цен. Номенклатура_Key, ВидЦен_Key, Характеристика_Key, Цена |
| `Catalog_Контрагенты`, `Catalog_ВидыЦен`, `Catalog_СтруктурныеЕдиницы`, `Catalog_Организации`, `Catalog_СостоянияЗаказовПокупателей` | GET ссылок по Ref_Key и Description |
| `Document_ЗаказПокупателя` | GET списка, POST нового заказа. Поля Date, Ref_Key, Контрагент_Key, Запасы, СуммаДокумента, СостояниеЗаказа. Связь Контрагент |
| `Document_ЗаказПокупателя(guid'<UID>')` | GET одного заказа. Вместо <UID> подставьте ключ, полученный в ответ на POST |

Тренажёр поддерживает сравнения `eq`, `ne`, `gt`, `ge`, `lt`, `le` и соединение условий через `and`, выбор полей через запятую, сортировку одного поля, `$skip`, `$top` и раскрытие контрагента заказа.

## Упражнения с запросами

1. **Доступ.** Проверьте URL публикации с верным паролем. Измените пароль в форме, получите 401 и верните прежний. Для запроса совсем без заголовка авторизации выполните в терминале команду ниже. В Windows используйте `curl.exe`.

   ```sh
   curl -i http://127.0.0.1:8080/unf_production/odata/standard.odata/
   ```

2. **Метаданные.** На вкладке «Произвольный запрос» укажите `$metadata`. Найдите набор заказов, поле Контрагент_Key и навигационное свойство Контрагент.
3. **Номенклатура.** В запросе к `Catalog_Номенклатура` задайте отбор `IsFolder eq false and DeletionMark eq false`, поля `Ref_Key,Description,Артикул` и сортировку `Description asc`. Проверьте три колонки и порядок. Снимите отбор, чтобы увидеть также папки.
4. **Группа.** В том же ресурсе найдите папку по отбору `IsFolder eq true and Description eq 'Блокноты'`. Скопируйте Ref_Key. Замените отбор на `Parent_Key eq guid'<UID папки>' and IsFolder eq false`. Сверьте число товаров.
5. **Остатки и цены.** На вкладке «Остатки» получите все строки и сумму. В справочнике `Catalog_ВидыЦен` найдите «Закупочная». На вкладке «Цены» сравните выборку без отбора и выборку `ВидЦен_Key eq guid'<UID вида цены>'`. Для проверки цены одного товара добавьте `and Номенклатура_Key eq guid'<UID товара>'`.
6. **Ошибки.** На вкладке произвольного запроса укажите `Catalog_НетТакого` для 404, затем учебный ресурс `Training_Error500` для 500. Верните ресурс каталога и проверьте обычный GET. Учебный ресурс 500 существует только в тренажёре.
7. **Создание заказа.** Найдите «ОфисПро Трейд» в `Catalog_Контрагенты`, затем два товара по артикулам `УЧ-0001` и `УЧ-0002`. Найдите их закупочные цены. На вкладке «Создание заказа» укажите 15 января 2027 года, UID покупателя и две строки с количеством 2 и 3 соответственно. Отправьте. Скопируйте UID из ответа 201.
8. **Раскрытие связи.** Прочитайте созданный документ по UID с параметром `$expand=Контрагент`. В интерфейсе укажите в поле связи только `Контрагент`. Проверьте вложенный Description, обе строки и сумму. На вкладке «Самопроверка» введите четыре числа и UID. Проверка заново прочитает ваш документ из сервиса.

### Пример POST для собственной обработки

Адрес — `Document_ЗаказПокупателя?$format=json`. Заголовок — `Content-Type: application/json; charset=utf-8`. В следующем примере уже подставлены постоянные UID учебного сервиса.

```json
{
  "Date": "2027-01-15T10:00:00",
  "Контрагент_Key": "6de0ede3-b287-5dc5-b1dc-eb621e729520",
  "Запасы": [
    {"LineNumber": 1, "Номенклатура": "903dd96e-128f-5e56-b400-a6d9179bab49", "Номенклатура_Type": "StandardODATA.Catalog_Номенклатура", "Количество": 2, "Цена": 83},
    {"LineNumber": 2, "Номенклатура": "b40e4b9c-db90-5337-9e8c-90094a072b8c", "Номенклатура_Type": "StandardODATA.Catalog_Номенклатура", "Количество": 3, "Цена": 90}
  ]
}
```

Возьмите Ref_Key из ответа и выполните `GET Document_ЗаказПокупателя(guid'<UID>')?$expand=Контрагент&$format=json`. Новый POST без Ref_Key создаёт новый заказ. Если клиент задал Ref_Key сам, повтор с тем же ключом вернёт 409. В этом случае прочитайте существующий документ через GET.

| Проверка | Ожидается |

| Только товары | 500 строк, пять страниц |

| Остатки | 500 строк, всего 486 150 шт. |

| УЧ-0002 | 594 шт., закупочная цена 90 ₽ |
| Заказ | «ОфисПро Трейд», 15.01.2027. Две строки на 166 ₽ и 270 ₽, всего 436 ₽ |
| Самопроверка | Четыре результата по выборкам и четыре по сохранённому заказу |

</details>

`catalog.csv` содержит выборку полей из учебного каталога «ОфисПро» версии 0.2.6. UID воспроизводимы внутри тренажёра. Ответы относятся к этому учебному набору. HTTP-тесты можно запустить командой `python3 test_trainer.py`. Они используют временную базу заказов.
