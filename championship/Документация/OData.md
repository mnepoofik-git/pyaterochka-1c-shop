# Обмен между производителем и «ОфисПро Трейд»

Корень сервиса учебного производителя — `http://localhost:8080/unf_production/odata/standard.odata/`. Клиент использует HTTP Basic и JSON. При обращении с другого компьютера в расширении требуется HTTPS. Форма «Клиент OData» сохраняет пароль профиля в безопасном хранилище БСП.

## Данные для запросов

| Ресурс относительно корня | Операция | Поля и назначение |
| --- | --- | --- |
| `$metadata` | GET | XML-описание опубликованных сущностей и навигационных свойств |
| `Catalog_Номенклатура` | GET | Ref_Key, Parent_Key, Description, IsFolder, Артикул, DeletionMark |
| `Catalog_Контрагенты` | GET | Ref_Key и Description. Для отправки требуется один действующий «ОфисПро Трейд» |
| `Catalog_ВидыЦен`, `Catalog_СтруктурныеЕдиницы`, `Catalog_Организации` | GET | Ссылки производителя для отбора закупочной цены, склада и организации |
| `AccumulationRegister_ЗапасыНаСкладах/Balance` | GET | Остаток КоличествоBalance по Номенклатура_Key и СтруктурнаяЕдиница_Key |
| `InformationRegister_ЦеныНоменклатуры/SliceLast` | GET | Последняя Цена по Номенклатура_Key, Характеристика_Key и ВидЦен_Key |
| `Document_ЗаказПокупателя` | POST, GET | Шапка заказа, табличная часть Запасы, Ref_Key и СостояниеЗаказа |
| `Catalog_СостоянияЗаказовПокупателей` | GET | Название типового состояния по ссылке |

## Примеры для вкладки «Запрос»

В поле «Ресурс» укажите имя из первого столбца. Параметры вводятся в отдельные поля формы без знака доллара. Для просмотра каталога задайте ресурс `Catalog_Номенклатура`, фильтр `IsFolder eq false and DeletionMark eq false`, поля `Ref_Key,Description,Артикул` и сортировку `Description asc`. При отправке по HTTP клиент кодирует значения параметров в URL.

Чтобы найти покупателя, укажите `Catalog_Контрагенты`, фильтр `Description eq 'ОфисПро Трейд' and DeletionMark eq false` и поля `Ref_Key,Description`. Для чтения связанного контрагента заказа используйте `Document_ЗаказПокупателя` и `$expand=Контрагент`. Имена доступных навигационных свойств показывает `$metadata`.

## Создание и отслеживание заказа

Пример структуры тела POST на `Document_ЗаказПокупателя?$format=json` приведён ниже. Вместо обозначений в угловых скобках подставьте Ref_Key покупателя и товара из базы производителя. Номер строки начинается с единицы. Цена в примере условная.

```json
{
  "Ref_Key": "<UID заказа поставщику>",
  "Date": "2026-11-21T10:00:00",
  "Контрагент_Key": "<UID покупателя>",
  "Комментарий": "OfficePro-<UID заказа поставщику>",
  "СуммаДокумента": 250,
  "Запасы": [
    {"LineNumber": 1, "Номенклатура": "<UID товара>", "Номенклатура_Type": "StandardODATA.Catalog_Номенклатура", "Количество": 2, "Цена": 125, "Сумма": 250, "Всего": 250}
  ]
}
```

Форма заказа сохраняет полученный Ref_Key. Повторная отправка сначала ищет документ по Ref_Key, равному UID локального заказа поставщику. Состояние читается запросом `Document_ЗаказПокупателя(guid'<UID>')?$select=Ref_Key,СостояниеЗаказа&$format=json`. Второй GET к справочнику состояний возвращает его название. Ошибки обмена записываются в журнал регистрации УНФ. Состояние локального документа «Отправлен» должно существовать в справочнике состояний заказов поставщикам.
